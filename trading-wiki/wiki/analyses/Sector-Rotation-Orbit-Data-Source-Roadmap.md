# Analysis: Sector Rotation Orbit — Data Source Roadmap — 2026-08-01

> [!key-insight] The question contains a wrong premise, and probing it found a live bug
> **yfinance already IS the orbit chart's data source — for the X axis.** `sector_rotation_trail.fetch_index_history` has always pulled trailing-1Y sector-index returns from yfinance. The gated half is only the **Y axis** (FII rotation score), and yfinance carries **no Indian ownership data at all**, so it cannot ever supply it.
> The right replacement already lives in this repo and is verified: **NSE's SEBI shareholding XBRL** ([nse_shareholding_fetch.py](tools/nse_shareholding_fetch.py), DS-2). Probing it live on 2026-08-01 turned up something else: **`quote-equity` now returns 403 for every symbol**, which means `build_dataset` — and therefore the whole **Other Screeners → Pipeline → Sector Rotation** path — is returning an **empty frame today**. Same silent-empty failure shape [[log]] recorded for DS-2, one layer down.

## Thesis

The orbit chart is the only surface in the dashboard still gated behind a **manual screener.in export** with `FII_<quarter>` columns, captured through a browser session. That is why its caption reads *"Requires a screener.in export"* and why it is regenerated by hand. Everything it needs is now obtainable **login-free**, but not from where the question assumed.

**What the chart actually plots** ([sector_rotation_trail.py](tools/sector_rotation_trail.py)):

| Axis | Meaning | Current source | Gated? |
|---|---|---|---|
| **X** | Sector index trailing-1Y return, as of each quarter-end | **yfinance** (`fetch_index_history`) | No — already free |
| **Y** | Cap-weighted Δ FII holding % by Industry | **screener.in CSV export** (`FII_<quarter>` columns) | **Yes — the blocker** |
| grouping | `Industry` label → one of 11 NSE sector indices | screener.in `Industry` → `SECTOR_INDEX_MAP` (97 keys) | Yes |
| weight | `Mar Cap` per stock | screener.in `Mar Cap` | Yes |

So the work is: **replace the Y axis, the Industry grouping, and the cap weight.** The X axis needs nothing.

## Evidence For — what was verified live on 2026-08-01

All of the following was probed directly, not assumed:

- **NSE shareholding XBRL works and is deep.** `get_shareholding_filings("RELIANCE")` returns **22 filings** (TATASTEEL: 28), quarterly back past Dec 2023 — *more* history than the trail's current Sep-2023-onward window. `fetch_ownership` parses clean: `reconciles: True`, categories total **100.00%**, promoter and public match the filing-master's independent fields. Full split available (FPI Cat I/II, FDI, DII, MF, insurance, banks, pension, AIF, retail small/large, NRI). **No login, no cookie.** `fetch_ownership(quarters=N)` already accepts an N-quarter parameter — the history API exists today.
- **Filings are immutable once filed**, so a per-`(symbol, period)` cache is permanently valid. Backfill is a one-time cost, then ~1 fetch/symbol/quarter forever.
- **The Nifty 500 constituent CSV is open**: `nsearchives.nseindia.com/content/indices/ind_nifty500list.csv` → **HTTP 200**, 500 rows, columns `Company Name, Industry, Symbol, Series, ISIN Code`. It supplies the universe *and* an Industry label in one login-free file.
- **yfinance supplies the cap weight**: `Ticker("RELIANCE.NS").fast_info["market_cap"]` → ₹17.7 lakh crore. Works, free.

## Evidence Against — the four real obstacles

1. **`quote-equity` is 403 — right now, for every symbol.** `fetch_industry_and_cap` is the only supplier of `Industry` and `Mar Cap` to `build_dataset`, and `build_dataset` *skips any symbol where either is None*. Verified across RELIANCE / TCS / TITAN / HDFCBANK / SUNPHARMA / TATASTEEL: **6 of 6 returned `(None, None)`**. The snapshot pipeline is therefore silently producing nothing today. This is a **live bug, not a roadmap item**, and it blocks the existing feature as well as the new one.
2. **The industry vocabularies are disjoint.** `SECTOR_INDEX_MAP` has **97 keys** of screener.in's fine-grained labels ("Private Sector Bank", "NBFC", "Computers - Software & Consulting") → 11 indices. The Nifty 500 CSV has **20 coarse NSE macro-sectors** ("Financial Services", "Capital Goods", "Metals & Mining"). Measured overlap: **0 of 20 key into the existing map.** A new mapping is required — but 20 hand-mapped entries is *cheaper* than the 97 it replaces, and a coarse taxonomy maps onto 11 indices far more honestly than a 130-way one ever did.
3. **The filing-master `industry` field is a decoy.** The response carries an `industry` key, which looks like it routes around the 403 — it is `'-'` for all 7 symbols tested. Do not build on it.
4. **Backfill is slow.** NSE rate-limits aggressively and the module sleeps 1.5 s between calls. Nifty 500 × 8 quarters ≈ 4,500 requests ≈ **~2 hours** one-time. Acceptable as an overnight job; unacceptable inside a Streamlit rerun. The cache is what makes this a one-time cost.

## Source comparison — the recommendation

| Source | Ownership history | Gated? | Precision | Verdict |
|---|---|---|---|---|
| **NSE SEBI XBRL** (in repo) | 20–28 quarters/symbol | **No login** ✅ | Full (4-dp fractions), reconciled to 100% | **✅ Recommended primary** |
| **yfinance** | **None for Indian ownership** | No | — | ✅ Keep for X axis + cap weight; **cannot** do the Y axis |
| **Trendlyne** | 12 quarters, public | **No login** (verified) | **1 decimal** (`0.2%`, `1.2%`) | ⚠️ Fallback only — see below |
| **screener.in** (status quo) | Deep | **Yes** — browser session | Full | ❌ Retire |

**On Trendlyne specifically**, since it was named: its shareholding table *does* render anonymously — verified 2026-08-01, showing 12 quarters of Promoter/FII/DII/Public plus SECTOR and INDUSTRY labels. It is genuinely usable. It is still the wrong primary, for three reasons: (a) **one-decimal rounding is lossy for a *delta* measure** — the Y axis is quarter-over-quarter *change*, so a real 0.04 pp move reads as 0.0, and the rounding error is the same order as the signal; (b) it is an **aggregator recomputation**, where we already hold the **regulatory filing itself** — the distinction DS-2 was built on; (c) a requested RELIANCE URL **redirected to a different company's page**, so programmatic access needs their internal ID mapping. Also: I did not read their Terms — check them before any systematic fetching. Recommend Trendlyne **only** as an optional backfill for quarters older than XBRL coverage.

## Conclusion — sequenced backlog

**SR-0 — Fix the 403 (bug, do first, ~1 h).** Route `fetch_industry_and_cap` off `quote-equity`: Industry from the cached Nifty 500 CSV, `Mar Cap` from yfinance `fast_info["market_cap"]`. Add a **loud failure** when a lookup yields nothing for the whole universe — the recurring lesson in this repo is that an empty result must not look like an answer. Unblocks the *existing* snapshot pipeline independently of everything below.

**SR-1 — Universe + taxonomy module (~2 h).** New `nse_universe.py`: cached fetch of `ind_nifty500list.csv` → `symbol → (name, industry)`, plus a new **`NSE_SECTOR_INDEX_MAP`** hand-mapping the 20 NSE macro-sectors onto the 11 sector-index tickers. Leave the 97-key screener.in map in place for the legacy CSV path. Depends on SR-0.

**SR-2 — Quarterly ownership cache + backfill job (~4 h, then ~2 h unattended).** On-disk store keyed `(symbol, period)` — immutable, so never re-fetched. A headless `--backfill` mode walking the Nifty 500 with the existing 1.5 s courtesy sleep and resumable progress. This is the load-bearing piece and the only expensive one.

**SR-3 — Wide emitter (~1 h).** Have `sector_rotation_trail` read the cache directly (preferred) or emit the `FII_<quarter>` wide shape `load_wide_export` already consumes. Deliberately keep `load_wide_export` working so an old screener.in CSV still runs.

**SR-4 — Wire the dashboard (~1 h).** Orbit chart regenerates from the cache; drop the *"Requires a screener.in export"* caption; keep the CSV path as an explicit fallback. Depends on SR-1…SR-3.

**SR-5 — True historical cap weighting (~3 h, quality).** The trail's own docstring flags that it weights **every historical quarter by today's market cap**. The XBRL carries share counts per filing; multiply by the quarter-end close (yfinance, already fetched for the X axis) for a real historical cap. Turns a documented approximation into a measured number.

**SR-6 — Price-only RRG tail, yfinance-only (~3 h) — RECOMMENDED SECOND.** The honest answer to *"can yfinance do it"*: yes, for a **different chart**. Plot RS-ratio vs RS-momentum against NIFTY per sector index with a historical tail — a textbook Relative Rotation Graph, **zero gating, zero new data**, all 11 indices already cached by `cached_fetch_sector_data`. It ships **without any of SR-0…SR-5** and answers "which sectors are rotating" on price alone. Note it is *not* a substitute: ownership flow and price momentum are different questions, and [[concepts/FPV-Flow-Price-Volume-Ownership]] is explicit that reading one for the other is the mistake.

**SR-7 — Trendlyne backfill (optional, only if SR-2 coverage proves short).** Second-class by construction: 1-dp values, flagged in the UI as lower precision, never mixed silently into XBRL-sourced quarters.

### Recommended order
**SR-0 → SR-6 → SR-1 → SR-2 → SR-3 → SR-4 → SR-5.**
SR-0 because a silently-empty pipeline is a bug shipped. SR-6 second because it is cheap, ungated, and delivers a working rotation view while SR-2's backfill is still being written. Then the ownership spine in dependency order.

## Action Taken / Plan

- **Budget:** SR-0…SR-5 ≈ 12 h of work plus ~2 h unattended backfill. SR-6 ≈ 3 h standalone.
